TRUST & RANGE

谁能接收？又能传多远？

鉴权频段板

把频率交给对的人

保存 Owner、读取 / 写入权限、隐藏鉴权主频与安装锁。普通板没有身份限制；鉴权板由服务端检查，未获准的玩家看不到隐藏主频。

电脑还受桥接器开放的读取、激活和配置能力约束。旧版凭证接口与当前信道槽的差别，见 Lua 完整参考。

长信号

跨距离，也跨区块加载状态

同维度收发端分别开启长信号，使用有效鉴权板。远端未加载时按需唤醒，原有频率与权限规则继续生效。

默认每位 Owner 额度 15。同设备同 Owner 的多个信道只占 1 份；不同 Owner 分别计数。实际额度以服务器设置与按钮提示为准。

拼接桥接器从信道槽位取得鉴权资格。

AFN 长信号命令与配额

长信号按钮提示开头的 已用 / 配额 表示登记设备数与当前额度，例如 3/15 表示已登记 3 台、额度为 15 台。额度按鉴权板的 Owner 在整个存档累计，跨维度共用。同设备的双槽或多个信道重复使用同一 Owner 只计 1 台；涉及多个 Owner 时，每位各计 1 台，且都须有额度。已登记的未加载设备仍计数；降低额度不会删除登记，暂未获准的设备也仍在使用量中。每设备默认最多启用 10 个长信号信道，服务器可调低。

额度接受 0～4096 的整数，0 禁用该 Owner 的长信号。优先级为：个人覆盖 → 本存档的服务器默认值 → 配置 infinite_range.default_owner_quota（默认 15）。set 写入个人覆盖；allset 保存服务器默认值，已有个人覆盖继续优先生效。两者均不替玩家开启设备。

命令权限等级作用
/afn longsignal set <用户名> <额度>3 级及以上设置指定 Owner 的个人额度覆盖。
/afn longsignal allset <额度> [confirm]4 级修改服务器默认额度；先请求，再确认。
/afn longsignal del <用户名>3 级及以上撤销该 Owner 的长信号登记并清除个人覆盖，之后回到服务器默认额度。
/afn longsignal alldel [confirm]4 级撤销所有已登记 Owner 的长信号并清除全部个人覆盖；保留服务器默认额度。
/afn longsignal find普通玩家仅查询自己占用额度的设备，列出名称、维度、位置和信道数；物理结构位置可能暂不可用。

用户名 按服务器玩家档案解析，可指定能被服务器解析到的离线玩家；@a 等玩家选择器只匹配在线玩家。find 只能由玩家执行，不接受目标参数。

allset / alldel 须由同一执行者在 600 个服务器 tick 内（20 TPS 时约 30 秒），再次执行原命令并追加 confirm；allset 的数额须相同。过期后重新请求。

删除命令会关闭相应长信号。 del 撤销所有计入该 Owner 的信道（包括副槽鉴权板），清理对应远程信号与加载租约；其他 Owner 的独立信道保留。未加载设备重载后也不会自动恢复旧开关，需重新启用长信号。设备方块与频率配置保留。
复制命令示例（将 FactoryLin 替换为实际用户名）+

为 FactoryLin 设置 20 台额度；玩家查询自己的设备：

/afn longsignal set FactoryLin 20
/afn longsignal find

将服务器默认额度设为 15，连续执行两条命令完成确认：

/afn longsignal allset 15

/afn longsignal del FactoryLin

/afn longsignal alldel confirm

信道是什么？

信道同时承载数据和激活信号。数据可以是文字、数字、布尔值或数组；激活强度为 0～15。频率让收发设备匹配，信道名则便于在桥接器与面板内引用数据。

改了数据，不代表已经发出激活。把内容写好后，还需要红石输入、修改后脉冲、定时或条件触发。

地图 JSON 字段逐项说明
字段含义、格式与省略行为
points顶层点列表，每项是 [x,y,z] 或点对象；只放点时可省略 lines、areas。
lines顶层折线列表，每条线各有自己的 points 顶点列表，按顺序连接，至少 2 个顶点。
areas / polygons顶层面列表，每个面至少 3 个顶点，按顺序连接并自动闭合。polygons 是桥接器地图的别名。
position / pos点对象中的世界坐标数组 [x,y,z]，单位为方块，允许小数。
x / y / z另一种点坐标写法：x 为东西方向，y 为高度，z 为南北方向；同时提供三个数值。
points（在线 / 面内）该线或面的有序顶点列表；每个顶点也可用点对象，单独设置名称或颜色。
name点、线或面的外显名称；省略则只画图形。label、title 也可作为名称别名。
color图形颜色；可用于集合、图形或单个顶点，较内层的有效设置覆盖外层，省略时继承设备 / 上级配色。
text_color / textColor名称的文字颜色，与图形色分别配置；省略时继承设备 / 上级文字配色。


color 控制图形色，text_color 控制名称色，推荐使用 #RRGGBB。未填时分别沿用桥接器对应配色；线、面的顶点默认继承图形配色，显式顶点配置优先。也支持 #RGB、0xRRGGBB、十进制 RGB 整数和 [r,g,b]。


线至少两点、面至少三点，按顶点顺序连接；areas 也可写成 polygons，线与面都可定义多个。存在图形时，自身到目标的自动连线设置不生效；图形本身照常显示。右下角的坐标和距离使用第一个点与设备自身。
点击仍是选择一个坐标。 点击会把信道数据替换为单点，不会向原图形追加顶点；附近点击会吸附显示点，包括线与面的顶点。游戏内“桥接器”帮助页签集中说明各交互模式与数据结构。

DP面板


在 Dashpanels 页签底部的 AFN Modules 中取得模块，放到面板上，用 Panel Wrench 打开属性。频率沿用 Panel Link 中该模块的两个槽位。鼠标悬浮模块物品并按住 V，可打开其原生 Wiki 页面，查看功能与各项配置。


控制滑杆
标准、长型、水平和长型水平四种滑杆配置一致，尺寸分别为 3×5、3×10、5×3 和 10×3 面板像素。长型的长度与大型雷达直径一致。


滑杆发送上下限之间的数值，默认范围为 0～100。开启“输出整数”后四舍五入；红石强度默认为 15，范围为 0～15。“改变后脉冲”默认开启：操控期间保持激活并连续更新数值，松手后保留 2 tick 短脉冲。激活条件独立生效，为真时也会保持激活；初始化、重载和配置变化不触发改值脉冲。


节点：填写 20,50,80 或 [20,50,80]，也可使用信道输出语法。只有上下限之间的节点生效，并在刻度侧显示标识。拖到途中的最近节点时，本次拖动停止；松开后再次拖动才能越过该节点。


灵敏度：拖动变化倍率，越小越细；标准滑杆默认 1，长型默认 0.4，支持信道输出语法。右键按住滑杆时可用滚轮微调，灵敏度为当前设置的一半，且忽略节点。


信道输出语法：留空时发送当前数值；填写纯文本时发送固定文本；填写含 ${...} 的表达式时发送计算结果，可用模块名称引用同一面板网络内的值。表达式无效或引用来源缺失时停止输出，不会沿用旧值。


配色：滑块、指针、刻度分别配置，支持 RRGGBB 或 #RRGGBB。节点标记沿用刻度色。


摇杆
拖动摇杆发送二维数组 [x,y]。两个角点分别限定 X、Y 轴取值范围，默认 -1,-1 到 1,1；可开启整数输出。角点、节点、强度、激活条件与输出均支持信道输出语法。
节点与记忆：节点支持 0,0、[[0,0],[1,1]] 或信道输出语法，默认节点为 [0,0]。记忆默认关闭，松手后匀速回到最近节点；开启后保持松手时的位置。“改变后脉冲”默认开启，操控期间持续激活并更新数值，松手后保留短脉冲。


仪表盘与显示模块
  • 扇形 / 圆形仪表盘：只接收单个数值，可配置名称、名称显示、上下限及背景、指针、刻度颜色。默认范围 0～100，超限时指针停在端点；圆形仪表盘占用更小。
  • 小型 / 大型无线电：显示寻呼机对话格式的最后一条消息，包括头像、名称和正文，也接受纯文本；右击可清空当前消息，可配置屏幕背景色和文字颜色。
  • 小型 / 大型信息板：直接显示信道内容，可配置屏幕背景色和文字颜色。
  • 按钮 / 开关：可设置名称、信道内容与信号强度，内容和强度均支持信道输出语法。按钮短按发送短脉冲，按住时持续发送，松开停止；开关开启时持续发送。按钮还可设置按压部件颜色。
  • 占位信道元件：扁平的 1×1 格中间信道，接收内容和强度，供同一面板网络内的表达式按名称引用，可配置颜色。


颜色支持 RRGGBB 或 #RRGGBB。空白内容只显示背景；接收模块在信号结束后保留最近一次内容。仪表盘隐藏名称不影响按名称引用，动效沿用 Dashpanels 本体。


雷达与大型雷达
两种尺寸共用相同配置，以模块自身的世界位置为圆心，显示桥接器地图支持的点、线、面及其名称，支持 Sable 移动结构；不绘制地形，不自动改变比例尺。坐标均为世界绝对 x,y,z，不是相对偏移。可接收单点、连续三项分组、多维数组或地图 JSON：


0,64,0
0,64,0,24,64,16

每行是一个独立示例。只有比例尺半径内的点才会显示；若坐标看不见，先检查其相对模块位置的距离，并增大比例尺。


{"points":[{"name":"基地","position":[0,64,0]}],"lines":[{"points":[[0,64,0],[24,64,16]]}],"areas":[{"points":[[0,64,0],[24,64,0],[24,64,16]]}]}

比例尺圆心到边缘的水平半径，单位为方块，有效范围 0.001～60000000，默认 64；越大显示范围越广，支持信道输出语法，非法或越界时保留上次有效比例尺。

{[0,64,0]:"基地",[24,64,16]:"码头"}


液晶能柱
提供竖向 1×4、水平 4×1，以及长型 2×10、10×2 四种分节电池状显示器，接收单个数值。上下限默认为 0～100；第一、第二节点划分低、中、高三个区间，默认颜色依次为红、黄、绿。节点留空时按范围三等分，节点和上下限均支持信道输出语法。

无线电接收寻呼机 JSON，显示最后一条消息的头像、名称和内容；纯文本按匿名消息显示。头像使用 item:物品注册名 或 player:玩家UUID。messages 可混排文字与存量对象，以物品图标作为表情显示：


{"avatar":"item:minecraft:apple","name":"仓库","message":"补货完成"}
{"name":"仓库","messages":["库存",{"minecraft:apple":8}]}


信息板则直接显示任意信道内容，不把 JSON 解析为对话。仪表盘和液晶能柱只接收单个数值，不接受包含多个数值的数组。


信道输出语法与预览
数值与内容输入框支持信道输出语法，包括滑杆的上下限、节点、强度、条件与输出，摇杆的坐标、强度、条件与输出，仪表盘的上下限，按钮 / 开关的信道内容与强度，以及地图的旋转、比例尺与固定点。滑杆和摇杆的输出语法留空时发送原始值；填写纯文本时发送固定文本；输入包含 ${…} 时，输入框下方显示求值预览。颜色输入框仍填写色值。


同一面板网络中的名称均可访问，包括合并底座上的全部模块与线缆连接的其他面板，名称须彼此不同。AFN 模块提供信道内容；原生模块只能读取信号强度，多路模块取各路输出的最大强度。


${滑杆名}
${strength($.开关名)}


上下限须得到有限数字且下限不大于上限；条件须得到布尔值。滑杆表达式无效时停止输出。

2. 连接并查看信道


电脑紧贴桥接器，或通过有线调制解调器接入。运行：


local afn = require("afn")

local bridge, bridge_name = afn.find()

预期能看到 door factory.door。afn、bridge、channel 都只是示例中的普通 Lua 变量名，可以换成别的名字。


3. 发送一秒信号


local afn = require("afn")
local result = afn.pulse("door") -- 默认强度 15、持续 20 tick
assert(result.success, result.error)



pulse 激活的是桥接器内已经存在的信道。该信道有有效主频，因此会发送 Create/AFN 无线信号；若主频为空，它仍会在桥接器内激活，但不会注册无线发送端。


4. 直接读写值


local afn = require("afn")

local before = assert(afn.value("door"))
print("before:", before.value)

local result = afn.set_value("door", "OPEN")
assert(result.success, result.error)

local after = assert(afn.value("door"))
print("after:", after.value)



普通覆盖不需要 revision。set_value 本身不等于激活；GUI 中另行配置的条件规则可能因值变化而激活。激活也不会自动创建值。


5. 设置主频和副频


local afn = require("afn")

assert(afn.set_primary_frequency("door", "factory.door").success)
assert(afn.set_secondary("door", "manual", "factory.zone_a").success)

-- 不需要副频时清除第二个普通频率：
assert(afn.set_secondary("door", "none").success)



副频模式有 none、manual、auth。none 清除副频，manual 写普通频率文本。当前拼接桥接器的鉴权板应由玩家在 GUI 的真实信道频率槽中配置；Lua 不能提交或重建 Owner、ACL、隐藏鉴权身份。auth 保留旧桥接器关联凭证语义；它不代表“在当前信道中新建鉴权板”，缺少旧凭证时不会获得有效鉴权无线链路。

可选参数、变量和 revision


方括号不是 Lua 代码


签名中的方括号表示可选：


afn.set_value(channel, value[, revision[, bridge_name]])



真正调用时不输入方括号。只有一台桥接器时通常省略最后的 bridge_name。指定最后一个参数而跳过中间参数时用 nil 占位：


afn.set_value("notice", "新内容", nil, "left")
afn.set_secondary("door", "none", nil, "left")



bridge_name 是 CC 分配的外设名，例如 left 或有线网络上的名称；不是信道名、方块标题或主频。


old、current 是什么


local current = assert(afn.value("counter"))



current 只是作者自取的局部变量，保存返回表：


{
  present = true,
  kind = "real",
  value = 12,
  revision = 7
}



它不是 AFN 关键字。换成 old、data、counter_state 都一样。


revision 为什么通常可以省略


只想把值改成指定内容时直接写：


local result = afn.set_value("notice", "列车即将进站")
assert(result.success, result.error)



只有新值依赖刚读到的旧值，例如“计数器加一”，才建议传旧 revision：


local current = assert(afn.value("counter"))
local result = afn.set_value("counter", current.value + 1, current.revision)

if not result.success and result.error == "revision_conflict" then
  printError("值已变化，请重新读取后计算")
else
  assert(result.success, result.error)
end



revision 是每台桥接器上的单调版本号。清除值也会推进 tombstone revision，因此“有值 → 无值 → 再有值”不会出现 ABA 误判。冲突后不要盲目循环提交，应重新读取并重新计算。

拼接屏幕与交互配置


当前使用可横纵拼接的桥接器屏幕，不需要旧大型 CRT 设备。先在 GUI 建立信道或用 create_channel 创建，然后配置选区和显示。布局 API 使用方块单位；单个选区没有旧的 4×4 上限，但须位于实际屏幕矩形内，且不能与其他选区重叠。




afn.screen([bridge_name]) / raw getScreen()


需要读取权限。返回 {adaptive,width,height,enabled,interaction_locked,revision,placements}；width/height 是整屏方块数，revision 是配置版本，不是值版本。每个选区包含 {channel,channel_id,x,y,width,height}，坐标从左上角 0,0 起算。




afn.set_screen(changes[, bridge_name]) / raw setScreen(changes)


需要配置权限。可修改 enabled、interaction_locked、placements，可带 expected_revision=afn.screen().revision 防止覆盖其他配置。未给出的字段保持不变；placements 是整份替换，空数组清空布局。条目用 channel 或 channel_id 标识信道；两者均给出时必须指向同一条信道。每条信道最多一个选区，选区可在已连接桥接器的屏幕边界内使用任意正整数宽高，但不能重叠或越界；矩形布局仅适用于拼接桥接器。


返回 {success,error,screen}，失败时原配置不变。关闭屏幕或交互锁不停止无线信道。


local afn = require("afn")
local screen = afn.screen()
assert(screen.width >= 2 and screen.height >= 2, "需要至少 2×2 屏幕")
local result = afn.set_screen({
  expected_revision = screen.revision,
  placements = {{channel="库存", x=0, y=0, width=2, height=2}}
})
assert(result.success, result.error)





afn.display(channel[, bridge_name]) / raw getChannelDisplay(channel)


需要读取权限。返回该信道的屏幕配置；未知信道返回 nil。读取只使用服务端发布的不可变快照，不等待 task_complete，不会抢占 timer 事件。




afn.set_display(channel, changes[, bridge_name]) / raw setChannelDisplay(channel, changes)

地图配置 GUI 可开启“动态模式”，使地图随桥接器所在 Sable 物理结构旋转；“旋转地图”用于校正方向，动态模式默认关闭。


激活条件引用本桥接器的信道，例如 ${温度} ≥ 30 & ${开关} = true 或 ${number($.温度)} > 25 || ${模式} = "手动"。引用自身读取原始值，引用其他信道读取有效输出；单项数组可直接比较，多项数组需选取或聚合。支持 = / ==、!=、<、>、>= / ≥、<= / ≤、& / &&、|| 和括号，优先级为括号、比较、并且、或者。条件为真时持续激活，空输出强度配置默认使用 15；设置强度表达式后按其结果输出。条件为假、缺值或错误时释放条件来源，其他来源不受影响；留空关闭。仅在引用的数据更新时按预算检测。GUI、.bridge 文件和 set_display 使用同一配置，语法错误会拒绝整次保存。


输出语法中的 add(a,b,...) 支持两个或更多参数，默认最多 8 项；sub、mul、div 仍为二元。原生单数字信道可直接用于数值函数，例如 ${add($.燃料1,$.燃料2,$.燃料3)}，无需 [0]；旧下标仍有效。多分量 REAL 和 JSON 数组需下标或聚合，不自动取首项。数字文本可用 number() 强制提取首个数值片段，周围文字会忽略，数值片段内的逗号也会忽略，例如 1,234,211 su 得到 1234211；文本中有多个数值时只取第一个。


if(test,yes,no) 要求布尔条件，只计算被选中的分支；缺失条件按 false 处理。switch(value,match,result,...[,default]) 按严格类型匹配并返回首个命中结果，可附最后一个默认值；匹配值须为标量 JSON 字面量，未命中且无默认值时返回 missing。两种函数都保留所有分支的信道依赖，但运行时只访问选中的结果。


为避免同频反馈，条件引用的其他信道及其输出依赖不得接收本条件信道的输出频率；自身原始值引用允许。


map_* 字段只允许在 map 模式下修改。文本选项写入值可继续调用 set_value；数组开关通过 chart_components 命名组内元素。物流模式的 presets 每项可填写接收端支持的调配语句，或使用一行 JSON 定义命名物资组：


local afn = require("afn")
assert(afn.set_display("库存", {
  mode="stock", show_name=false, show_idle=false,
  control_color=0xD8E7CE, background_color=0x17251B
}).success)

local group = textutils.serializeJSON({name="苹果配送", items={
  {item="minecraft:apple", count=8, address="餐厅"}
}})
assert(afn.set_display("配送", {mode="logistics", presets={group}}).success)

assert(afn.set_display("导航", {mode="map", map_source="xaero",
  map_show_connection=false, map_show_distance=true}).success)



物流屏幕由玩家选择物资组后发送。CC 主动调配仍使用现有 set_value 写入合法语句，再用 pulse 激活；配置物资组本身不会发单。存量视图解析存量信箱输出，仅显示物品图标与数量。地图滚轮以焦点缩放，中键仅平移；右键选点或外部普通/长信号更新为不同的合法坐标后，仅在任一点越界时自动适配，两点可见则保持视野。显示地图时，设备水平移动也会触发低频检查：两点可见便保持视野，任一点越界才适配；未移动不适配，中键拖动和待确认草稿优先。相同数据和 CC 写入不自动跟随。开启二次确认时，草稿保持原视野，成功确认后才判断是否适配；编辑期间的无线适配等草稿结束后再判断。


get_display_channel/set_display_channel/next_display_channel/previous_display_channel 继续保留旧选中项语义，不移动拼接屏幕的选区。set_display_channels/set_channel_displayed 控制展示资格，不自动分配矩形；新程序请明确配置 placements。

兼容迁移


    

  • raw 索引为 0～42；新增屏幕方法只追加在原有 0～38 后，旧脚本的函数名称与参数保持兼容。
    • 

  • createChannel/updateChannel 使用 receive_enabled 切换“仅发送”与“允许发送和接收”；没有独立的启用状态。
    • 

  • afn.information/set_information 保留，现映射统一可选值；推荐 value/set_value/clear_value。
    • 

  • set_channel_type/set_information_subtype 保留但弃用；它们只表达旧意图，不能恢复互斥存储模型。

想把其他模组接入 AFN 信道系统，该从哪里开始？+
前往 GitHub 的 API 目录，打开 create_afn-channel-api.jar 并点击 Download raw file 下载。目录也提供 Javadoc 与接入示例。
按 SDK 快速开始以 compileOnly 引入，只使用 com.createafn.api.channel 公共接口。当前 SDK 要求 AFN 1.1.6+，Channel API 为 1.1。运行环境安装完整 AFN；API JAR 只用于开发，附属成品不打包 API 类。
